## 2. Fluxos críticos percorridos (Iron Law 1)

### Fluxo J0 — First-time experience (NOVO P0 prospect-first)

**Cenário:** dev acabou de descobrir tracker no GitHub. Clonou. Rodou `npm install` + `docker compose up` + `npm run migrate` + `npm run dev`. Abre `http://localhost:5173`.

| Passo | O que acontece | ✅/⚠️/❌ |
|---|---|---|
| 1 | Vê LoginPage (`LoginPage.tsx:14-23`) — card centralizado simples, sem branding, sem hero, sem context | ❌ |
| 2 | "Login" ou "Criar conta" — escolhe Criar conta porque é first-time | ⚠️ |
| 3 | Form: email + password. Cria conta. **Vira super_admin automaticamente** (per README L37) | ⚠️ |
| 4 | Redireciona pra `/dashboard` | ✅ |
| 5 | Vê tela vazia "Nenhum dado ainda" (`DashboardPage.tsx:67-83`) com CTA "Ir para Configurações" | ⚠️ |
| 6 | Clica → vai pra Settings. Vê BRL rate, plan cost, daily budget, weekly reset, **WebhookInfo, CsvImport** | ⚠️ |
| 7 | Copia webhook token. Vai instalar coletor. Lê README. Volta. Cola token. | ⚠️ |
| 8 | Configura Tampermonkey OU Python hook OU Codex collector. Volta ao tracker. | ⚠️ |
| 9 | Espera primeira métrica chegar. **SEM feedback visual de que webhook tá ativo.** | ❌ |
| 10 | Volta ao Dashboard. Vê números. **NÃO existe celebração** "you're tracking!" | ❌ |

**Veredicto:** ❌ **Quebrado pra prospect**. Funcional pra Patrick (criou ele mesmo, sabe onde tudo está). First-time experience é catastrófica:
- LoginPage sem branding = não passa credibilidade Artemis
- Vira super_admin sem onboarding wizard = perdido
- Setup coletor 100% README-driven = barreira técnica desnecessária
- Sem verify connection = não sabe se webhook funcionou
- Sem celebração primeiro hit = engagement zero

**Severidade Nielsen:** 4 (catástrofe — bloqueia uso).

## 3. Findings consolidados (heurísticas Nielsen + WCAG)

### F1 — Onboarding wizard inexistente [Sev 4]

- **Evidência:** `App.tsx:43-44` redireciona Login → Dashboard sem checkpoint. `DashboardPage.tsx:67-83` empty state vai pra Settings mas Settings é página técnica, não wizard.
- **Heurística:** Nielsen #10 (Help and documentation) + Norman (Conceptual model alignment).
- **Impacto:** prospect first-time abandona setup. Conversion funnel quebra na etapa 3 (Trial→Use).
- **Recomendação:** wizard 4 steps conforme `01-strategy.md` §8. Detecta primeira sessão (`user.created_at < 24h && entry_count === 0`) → renderiza `<OnboardingWizard />` em vez de Dashboard.
- **Critério aceite:**
  - First-time user vê wizard, não Dashboard direto
  - Wizard cobre: pick sources / install hooks / verify connection / pricing review / personal goals
  - Pode skip ("Definir depois") mas com aviso
  - Após wizard completo, flag `onboarding_completed` salva DB
  - Test: criar conta nova → ver wizard

### F2 — Custom pricing input por modelo inexistente [Sev 4]

- **Evidência:** `server/src/config/pricing.ts:34-49` (referenced em PLAN-B-SPEC.md) — tabela hardcoded de pricing. Modelos novos = cost calculado errado ou 0.
- **Heurística:** Nielsen #5 (Error prevention) + Norman (Affordance: tracker promete trackar QUALQUER LLM via hook custom).
- **Impacto:** posicionamento "qualquer LLM" (Wave 1) é mentira sem custom pricing.
- **Recomendação:**
  - Toast Sonner "Novo modelo detectado: X" quando entry chega com model não registrado
  - Drawer/modal lateral com inputs ($X/1M input + $Y/1M output + $Z/1M cache) + preset dropdown (Claude/GPT/Gemini family)
  - Save → cost retroativo recalcula sessões anteriores
  - Settings ganha tab "Pricing" pra revisar/editar
- **Critério aceite:**
  - Entry com model desconhecido dispara toast
  - Após save, cost > 0 calculado
  - Pricing por usuário (não global) — single-tenant
  - Test: post webhook com model novo → ver toast → set pricing → cost calc

### F3 — Setup coletor 100% README-driven [Sev 4]

- **Evidência:** `SettingsPage.tsx:30-32` mostra WebhookInfo mas instruções de instalar Tampermonkey/Python hook/Codex collector estão no README (`README.md:38-90`).
- **Heurística:** Nielsen #10 (Help and documentation) + Nielsen #6 (Recognition rather than recall).
- **Impacto:** prospect alterna README ↔ tracker ↔ IDE 5+ vezes. Fricção mata conversion.
- **Recomendação:** wizard Step 2 mostra cada coletor inline com:
  - Comando único copy-paste (ex: `curl -fsSL .../install-claude-hook.sh | bash`)
  - ENV vars prefilled com webhook URL + token
  - Botão "Test connection" → tracker espera 1 hit → ✅ verde
- **Critério aceite:**
  - Cada coletor (Claude Code / Codex / Tampermonkey / Custom) tem aba inline
  - Comando 1-step pra source comuns
  - Test connection retorna success em <30s após instalar
  - Test: nuke local hooks, reinstalar via wizard → ver verde

### F4 — Streak counter inexistente [Sev 3]

- **Evidência:** sem componente streak em `client/src/components/`. AchievementsPage existe mas é catalog, não daily streak.
- **Heurística:** Nielsen #1 (Visibility of system status) + Laws of UX (Hick's Law inversa: gamification reduz fricção de retorno).
- **Impacto:** retenção subaproveitada. Wave 1 decidiu pilar de retenção.
- **Recomendação:**
  - `<StreakCounter />` na sidebar bottom (acima Configurações) ou Dashboard top
  - "🔥 12 day streak" + tooltip com goal
  - Reset rule: 1 dia inteiro sem entrada → reset; toggleable em Settings
  - Marcos motion (7/30/100/365) → AchievementUnlockMotion (Wave 3 motion-design define spec, P2 brand-heavy permitido)
  - Streak lost screen empático
  - Share button (screenshot dashboard pra Twitter/X)
- **Critério aceite:**
  - Counter visível e atualiza diário
  - Reset funciona (test: avança clock 25h sem entry → vê 0)
  - Marcos disparam motion + toast
  - Toggle off em Settings respeitado
  - prefers-reduced-motion respeitado

### F5 — Dashboard sobrecarregado verticalmente [Sev 3]

- **Evidência:** `DashboardPage.tsx:96-147` renderiza 9 blocos: PageHeader + SummaryCards + DailyBudgetProgress + DashboardFilters + BudgetAlert + MonthNarrative + PlanIndicator + 2-col charts grid + DailyCostChart.
- **Heurística:** Nielsen #8 (Aesthetic and minimalist) + Laws of UX (Miller's Law: sobrecarga cognitiva).
- **Impacto:** MonthNarrative (gem) enterrado em viewport <1080px. Above-the-fold é só headers + summary genérico.
- **Recomendação Wave 6.1 (Dashboard):**
  - Hero zone (above fold): MonthNarrative elevado + StreakCounter + KPI principal "tô estourando?"
  - Mid zone: SummaryCards condensadas (5→4 ou 5→3 essential)
  - Charts grid mais abaixo
  - DailyBudgetProgress consolidado com PlanIndicator (1 componente, não 2)
  - Eliminar BudgetAlert top (já tem PlanCountdown na sidebar)
- **Critério aceite:**
  - Above-the-fold em 1080p mostra: PageHeader + StreakCounter + MonthNarrative + 1 KPI bloco
  - "Tô estourando?" tem 1 lugar único (sidebar PlanCountdown), não 4
  - Test: visual QA matrix em 320/720/1080/1440

### F6 — 4 componentes redundantes pra "tô estourando o plano?" [Sev 3]

- **Evidência:**
  1. Sidebar `PlanCountdown` (`Sidebar.tsx:37-63`) ⭐
  2. Dashboard `DailyBudgetProgress` (`DashboardPage.tsx:116`)
  3. Dashboard `BudgetAlert` (`DashboardPage.tsx:120`)
  4. Dashboard `PlanIndicator` (`DashboardPage.tsx:132-138`)
- **Heurística:** Nielsen #8 (Minimalist) + Norman (Conceptual model: 1 fact, 1 surface).
- **Impacto:** squint test confirma redundância semântica. User não sabe qual prevalece.
- **Recomendação:**
  - **Manter:** Sidebar `PlanCountdown` (gem, sempre visível)
  - **Consolidar:** PlanIndicator + DailyBudgetProgress em 1 componente Dashboard ("Plan & Daily Budget")
  - **Remover:** BudgetAlert (PlanCountdown sidebar substitui)
- **Critério aceite:** redução de 4 → 2 componentes. Mantém visibilidade sem repetição.

### F7 — LoginPage sem branding/credibilidade [Sev 3]

- **Evidência:** `LoginPage.tsx:14-23` renderiza só LoginForm/RegisterForm centralizado. Zero hero, logo, tagline, posicionamento.
- **Heurística:** Norman (Conceptual model: prospect precisa entender produto antes de cadastrar) + Laws of UX (Anchoring: primeira tela ancora qualidade percebida).
- **Impacto:** prospect cria conta sem saber o que é. Reduz trust em Artemis.
- **Recomendação Wave 6.4 (Login):**
  - Layout 50/50 split (esquerda hero, direita form) — padrão DS preset default
  - Esquerda: tagline ("Plausible pra Claude") + 3 bullet features (cost track / streaks / multi-source) + footer "Built by Studio Artemis"
  - Direita: form (login/register toggle) + link "Modo demo (dados fake)" pra prospect testar antes
  - Visual: P2 brand-heavy permitido (Wave 3 motion define entrance + Wave 5 lift do `LoginScreen.jsx` canonical)
- **Critério aceite:**
  - 50/50 split visível em 1280+
  - Hero comunica produto em <10s
  - Logo Artemis pequeno presente
  - Modo demo opcional funciona (popula DB local com fake data)

### F8 — Loading states inconsistentes [Sev 2]

- **Evidência:** UX_AUDIT_SPEC F8 confirmou. `DashboardPage.tsx:23-39` tem skeleton rico. `SessionsPage.tsx:149-153` tem skeleton mas `AppLayout.tsx:50-55` mostra "Carregando..." raw text.
- **Heurística:** Nielsen #1 (Visibility) + perf percebida (CLS).
- **Recomendação:** `<AppLoadingState />` shared. Skeleton em todas pages que esperam data assíncrona. Texto "Carregando..." só em transitions <100ms.
- **Critério aceite:** zero "Carregando..." plain text em loading >150ms. Skeleton aparece consistente.

### F9 — Filtros de data com 3 implementações [Sev 2]

- **Recomendação:** consolidar em `DateRangeFilter` shared. Já existe — refactor pra todas pages.
- **Critério aceite:** grep `DashboardFilters` retorna zero ocorrências fora de migrations.

  - Wave 6.9: header sidebar mostra "Claude Token Tracker · by Artemis" com logo small

### F11 — Empty Dashboard CTA fraco [Sev 2]

- **Evidência:** `DashboardPage.tsx:67-83` — empty state diz "Nenhum dado ainda" + CTA "Ir para Configurações". Não faz pitch, não educa.
